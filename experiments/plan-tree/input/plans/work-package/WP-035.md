### from "Follow-up 2026-10-13 — the observation link needs a source, not only a distance"

The decision owner asked whether loosening :data:`SAME_FEATURE_TOLERANCE_ANGSTROM`
would give the single-hypothesis stage more candidate features. It would not (that stage
enumerates by its own z-window; this constant is read after every model stage), and
checking the question against the retained runs exposed two defects in this
projection. **What the tolerance actually compares.** The single-hypothesis skill prefers a
credible CWT feature and only fits when none exists, so a row records exactly one
kind of centre. The rule therefore compares the row's adopted centre against the
independent CWT catalog, which means two different things: | Row kind | Meaning of ``|Δ| ≤ SAME_FEATURE_TOLERANCE_ANGSTROM`` | Measured (5 fixtures × 6 hypotheses) |
|---|---|---|
| Carries CWT attributes (145 rows) | transcription/consistency: the model should have copied the catalog value | median 0.00 Å, 144/145 within tolerance |
| Fit-only (148 rows) | not a same-feature comparison at all: the nearest catalog entry is a different feature or absent | median 197.7 Å, 145/148 beyond tolerance | **Defects fixed here.** 1. *No source gate.* `_resolve_observation` matched every row with a finite centre, so a **fitted** row could be attributed to whatever CWT feature happened to lie within one Å — an identity the analyst never claimed. `_detector_derived` now requires `source == "CWT"`, or, for artifacts written before that column existed, CWT ridge/SNR attributes; the reason records which condition failed.
2. *No status gate.* `NOT_FOUND`/`MASKED` rows were matched too, so a leftover centre from a rejected fit could produce an ``observed_in`` edge contradicting the claim's own assertion. Measured incidence: 1 row (LRG_1 `[O III]a`, `NOT_FOUND`, centre 6292.0 coinciding exactly with a catalog entry). **Schema parity.** `write_lines_csv` now writes `source` and `implied_z` (14 columns,
mirroring the synthesis catalog's provenance fields), the single-hypothesis skill
documents them and states that traceability attributes a row to a CWT detection only
when `source` is `CWT`. The auditor path's `catalog_row_ref` gate already required
that column; it was inert for harness artifacts because they never carried it, and
now it can fire for rows that declare a detector measurement. **Tests.** Four projection tests (fitted row not attributed; row without provenance
not attributed; legacy CWT attributes still link, so archived artifacts keep their
links; `NOT_FOUND` with a leftover centre not linked) and two SH tool tests
(`source`/`implied_z` persisted; a written `CWT` row resolves through
`catalog_row_ref` while a `fit_peak` row does not). Suites: 184 evidence + 269
reasoning + 21 runtime + 6 evaluation. **Recorded, not fixed here.** Two model-behaviour observations surfaced while
measuring: one CWT-sourced row wrote a centre 1.86 Å away from the catalog value it
should have copied (`QSO_116` Hε), and several non-detection rows carry a non-null
`fitted_center` where the skill asks for `null`. The first is a prompt-compliance
question for the skill owner; the second is now neutralised by the status gate but
still worth a look. The **coverage** gap — fit-only measurements have no graph node
at all, roughly half of all rows in the retained runs — is not addressed here: it
needs its own model-derived measurement node and belongs to `WP-036`/`WP-037`. **Split into two judgements and renamed.** Follow-up review asked what the constant
actually means now that only CWT-derived rows reach it. It means *which* observation
a row refers to — not whether the digits were copied correctly — so the two questions
were separated and both thresholds moved to the layer that owns catalog-to-graph
referencing, `ontology/evidence_refs.py`: - `SAME_FEATURE_TOLERANCE_ANGSTROM` (1.0 Å) settles the referent: a unique feature of the expected kind within it is the observation the claim cites. When nothing lies inside it, the recorded reason now also names the distance to the nearest feature of the expected kind, so "no coverage" and "too far" are distinguishable.
- `CATALOG_COPY_TOLERANCE_ANGSTROM` (0.1 Å) checks fidelity: a row that *declares* `source=CWT` should carry the catalog value, so a deviation above this is recorded in the `observed_in` edge's `note` (`declared CWT centre differs from the catalog entry by X A`) instead of withholding a link whose referent is not in doubt. The builder no longer defines either threshold, so the rule-trace path and the graph
projection cannot drift apart. Measured effect over the 145 gate-passing CWT rows in
the retained runs: 142 within 0.1 Å, **2** in (0.1, 1.0] Å (now flagged on the edge),
**1** beyond 1 Å (unlinked, with the nearest-feature distance recorded). Three
further tests cover the fidelity note, the faithful-copy case and the nearest-feature
hint. *Names:* the two thresholds described above became declared empirical parameters in
`WP-040` — `parameter:evidence.same-feature-tolerance` (1.0 Å) and
`parameter:evidence.catalog-copy-tolerance` (0.1 Å) — and `evidence_refs` now exposes
them as `same_feature_tolerance_angstrom()` / `catalog_copy_tolerance_angstrom()`
instead of module constants. The rules themselves are unchanged.

### from "Follow-up correction 2026-10-14 — ownership and fatal finding attribution"

The reacceptance above was too broad in two respects. A second review reproduced
both problems; this correction supersedes its node-type ownership and rule-ID
substring claims. 1. `_clear_projected_layer` treated every `hypothesis`, `claim`, `quality_issue`, `decision` and `line_identity` as its own. An independent `quality_issue` was deleted merely because it shared a type. It now identifies owned nodes by the exact `provenance.method` that this builder wrote, removes their outgoing edges, and preserves foreign nodes and foreign-origin edges to nodes recreated on reprojection. An external edge to a withdrawn claim is removed **and reported** as a projection problem, so the saved graph remains valid without a silent stale reference. Regression tests cover surviving foreign issues and registry lines, a surviving foreign edge, and a reported edge to a withdrawn claim.
2. `_issue_severity` previously promoted any `spectrum_issues` text containing a `fatal_cap.rule_ids` value. Thus "Could not verify rule X" could become fatal. It now requires an exact auto-appended `rule_id: verdict` message backed by a structured `rule_findings` entry that is applicable, failed, fatal eligible, and belongs to the selected fit; the rule must also be in the fatal-cap set. Free-text mentions and legacy records lacking that finding remain warnings. An auditor-authored `Fatal:` sentence remains an explicit auditor severity claim. Tests cover the fatal finding, an unrelated note, rule mentions and an incomplete older record and a finding for a different fit. The narrowed ownership convention is explicit: a builder that wants an edge to
survive re-projection originates that edge at a node it owns; otherwise the
projection will rebuild its own outgoing edges. `WP-036` can use this contract
when it links rule findings to claims or decisions. Verification: 54 `test_analysis_projection.py` tests pass; the complete offline
suite passes 543 tests with proxy variables removed from the test process. Plan
validation and generated-view checks pass. The WP-023 frozen comparison was
regenerated because its adapter source digest includes `analysis.py`; its four
records differ from the prior record only in that digest. No FITS/LLM run was
performed; that remains `WP-037`.
