# ST-007 — Add telemetry, budgets, and adaptive execution modes

## Scope

Make runtime cost observable and route spectra through fast, standard, or forensic analysis under explicit budgets.

## Completion

- Components are implemented; status: **blocked** while `WP-013` and `WP-014`
  remain open. They cover telemetry and budgets, and execution-mode enforcement
  respectively.

## Review 2026-10-10

- **Runtime modules pass unit tests but are not enforcing the stated modes.**
  `RiskRouter` and `BudgetController` have no call sites in the production
  workflow; policy tests assert that limits are positive, not that execution
  stops at them. No typed graph-query capability is registered in the harness.
- The orchestrator records only workflow-attempt stages. Its production path
  never calls `record_model_call()` or `record_tool_rounds()`, so emitted counters
  remain zero. `ResultWriter.write()` runs only after `run_analysis_single()`
  returns in `scripts/main.py`; an exception does not persist failed-run
  telemetry. The telemetry schema also lacks the budget state named in
  `WP-013` acceptance. The claimed wall/call/token/stage coverage and failed-run
  output therefore need actual wiring and integration tests before `done` is
  justified.


## Review response 2026-10-10

Telemetry context is set around the workflow, BaseAgent records model-call
usage, failed-run telemetry is persisted, and a routing decision is recorded
after VisualInterpreter. Budget enforcement and full production counters are
still pending, so status is `blocked`.

### Update 2026-10-10 — budget enforcement added

`WorkflowOrchestrator._check_budget()` now enforces the active mode budget at
every node boundary; an exceeded budget raises `BudgetExceeded`. Full call/token
instrumentation across every harness path remains open.

## Completion 2026-10-12

WP-013 (structured telemetry, real-run evidence from the five-fixture
validation and the 32 calibration runs) and WP-014 (adaptive routing,
early stop, escalation) are both done; the short-term acceptance follows
from their records.

## Review follow-up 2026-10-12

WP-014 is reopened because the production router supplies constant ambiguity
inputs, the persisted decision can disagree with an escalation override, and
the live fast runs demonstrate budget stops rather than successful early
stopping. This parent returns to `in_progress`; the telemetry and budget
implementation evidence remains valid.

## Dependency update 2026-10-16

The decision owner cancelled WP-012's independent expert defect-grade gate.
WP-014 no longer depends on it and resumes `in_progress`; its own runtime
routing, fast-path and escalation evidence is still required before ST-007
can close. See `_aiHumanInteract/plan/evaluations/wp012-calibration-cancellation-20261016.md`.

## Superseded 2026-10-16

ST-013 replaces the remaining latency-first route and live fast/escalation gates. Completed WP-013 telemetry and budgets remain reusable; WP-014 is discontinued, not done.

See `_aiHumanInteract/plan/evaluations/agentic-graph-reasoning-pivot-20261016.md` for the decision and successor mapping.
