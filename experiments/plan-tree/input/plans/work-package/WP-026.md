# WP-026 — Refactor batch prompt rendering

## Objective

Apply the input contract to the model-facing stages, beginning with Redrock single-hypothesis verification.

## Planned work

- Split data gathering, ontology lookup, validation and rendering in the SH builder; preserve effective instructions and line status semantics.
- Migrate the other active prompt builders using the same contract where it removes hidden inputs or mixed authority. Keep stage-specific renderers where their content differs.
- Label and bound prior-agent reports and external data as evidence. Move imperative instructions out of data sections; enforce file/tool boundaries in code.
- Record the render version and effective prompt metadata at invocation time.

## Decisions

- Renderers may remain Python functions. A template engine is justified only by a demonstrated maintenance benefit and equivalent tests.

## Completion

- Planned; blocked by the WP-025 contract.

## Evidence

- To be recorded from code review, rendered fixtures and invocation traces.
