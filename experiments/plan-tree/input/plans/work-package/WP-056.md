# WP-056 — 修复 continuation 的无效工具调用重放

## Objective

修复 SH 线审的 continuation 修复轮：模型返回损坏的工具调用时，当前实现把 `invalid_tool_calls` 原样重放，提供方因缺少对应 tool 消息而返回 HTTP 400，整条样本中止。目标是让重放序列合法，并在仍被拒绝时用一次不带历史的新会话重试。

## Planned work

- 在 `node_runtime` 增加 tool-call 序列修复：为 `invalid_tool_calls` 与未应答的 `tool_calls` 紧接原 AI 消息补一条合成 `ToolMessage`（携带相同 call ID 与错误说明）。
- `repair_incomplete_stage` 在重放前调用该修复，并把合成响应写入会话归档。
- `MarkdownSessionRecorder` 打印 `invalid_tool_calls`（此前完全不可见，是本次诊断困难的直接原因）。
- 在 `sh_line_review` 中捕获 `BadRequestError`：一次全新会话重试，只带原始 user 提示与包含 `rows_to_repair` 的修复指令；仍失败则按现有严格策略失败。
- 增加离线测试：序列修复、记录器输出、全新会话回退。

## Decisions

- 2026-11-02 — 决策人选择 **A + C**：先合成 tool 响应并重放；若提供方仍返回 400，再执行一次全新会话回退。不做“单假设失败降级为部分完成”。
- 2026-11-02 — 合成响应只描述“调用格式损坏/未应答”，不替模型编造科学判断。

## Completion

- 状态：**done**（2026-11-02）。重放前为无效/未应答工具调用补合成 `ToolMessage`；会话归档显示 `invalid_tool_calls` 与合成响应；`BadRequestError` 触发一次全新会话回退。
- 验证：`tests/agentic_graph` 202 条通过（新增 6 条），其中序列修复在 `_convert_message_to_dict` 下无悬空 `tool_call_id`。
- 真实回放（120/H2）：对照组复现提供方 400（`insufficient tool messages following tool_calls message`）；修复组无 400，模型重发并写出 23 行有效表。
