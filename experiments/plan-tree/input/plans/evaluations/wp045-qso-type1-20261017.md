# WP-045 QSO Type 1 Q4–Q10 integration, 2026-10-17

## Implemented boundary

`qso_type1_path.py` extends the active Q3 branch through Q4–Q10 and returns a
Q10 terminal record for Q11. It reads the frozen SH catalog and NPZ by digest,
uses branch-local SH×FA pairing/width state, and stores each node and model
session in an allocated execution directory. The graph does not consume the
feature-level skyline risk property. The read window, odd vote count and bounded
attempt count are declared in the tracked `config/analysis_method.example.json`
under `qso_type1`; the local ignored `config/analysis_method.json` can override
them for a run.
Q4 stores the effective QSO and Gaussian-fit method snapshot and its digest;
Q7 fitting and Q8 point validation use this single loaded snapshot.

Q5 only reports `fully_masked` when explicit intervals cover the *whole*
requested local window and there are no usable samples. Missing or invalid
IVAR is `no_usable_data`; partial coverage remains partial. Q6 receives all
local samples and must distinguish an absorption-fragmented broad envelope
from CWT absence. Q7 gives its targeted observation a new ID, retains the
original SH/FA pairing, and checks a separate broad Gaussian width. A single
Gaussian fit on a fragmented envelope does not certify width; that branch is
left unresolved. Q8 compares raw peak-minus-saddle differences from the same
kind of spectrum view in both windows. Each point-selection session sees only
one anonymous window. Fresh comparison sessions receive just one paired ratio
and no earlier point-selection reasoning. Failed/invalid attempts and missing
quorum do not become positive votes. Q9 and Q10 are deterministic.

## Limits

The QSO_4 archived graph goes straight from trusted `[Ne V]` to the project's
Type 2 exit, so it cannot validate Q4–Q10 on a real Type 1 spectrum. The
synthetic checks establish orchestration, schema, mask and vote behavior; they
do not validate the scientific adequacy of a single targeted Gaussian fit,
the Q6 finding, or the Q8 acceptance votes. Q7 candidates have not been
independently re-reviewed by FA. A real labeled Type 1 FITS route and expert
review of unresolved/fragmented cases are still needed before using this
path as a calibrated classifier. The graph-wide workflow runner is separate.

The first broad discovery command omitted `-t .`, so `tests/evaluation` shadowed
the repository's `evaluation` package and five imports failed. The corrected
command exposed four failures: three SH→FA graph modules had re-spelled the
`LIKELY`/`MARGINAL` set instead of using `core.line_status`, and a historical
comparison test required the current executable-source digest to match the
archived digest even after source changes. The three graph modules now use the
central vocabulary with strict status validation. The historical comparison
still compares every decision and referent field exactly; it validates the
current digest separately as provenance, while preserving the archived digest.
