# WP-044 — Feature state and branch lineage contract

## Objective

Define the SH-to-FA state handoff and reversible branch history before building downstream graph reasoning.

## Planned work

- Import the frozen SH pre-analysis artifacts without requiring SH to emit question nodes.
- Define run-shared CWT and hypothesis-scoped Gaussian feature identities, immutable FA votes and projected observed-signal state.
- Define a JSON branch tree: fork at a named analysis event, snapshot the state there, preserve the parent and all result artifacts.
- Replay all six archived QSO_4 SH outputs, the one real FA vote and labeled offline fixture votes to check branching and state isolation.

## Decisions

- 2026-10-16 — Takes over the useful graph-capability and safety-budget aspects of WP-014 while ending its latency-first fast-routing acceptance.
- 2026-10-16 — The decision owner chose a new implementation boundary rather than moving most old code into a backup directory. The original pipeline remains the comparison path. Initial Markdown/Canvas designs are preserved as sketches, not accepted rules.
- 2026-10-16 — The decision owner clarified that the old Evidence Graph must not be the new graph's foundation. An earlier preparation note proposed it as an evidence substrate; that proposal is withdrawn. WP-031/WP-036 are no longer hard prerequisites; their records may be consulted, but the new schema and state are designed independently.
- 2026-10-16 — For the first SH node, reuse the existing Redrock SH skill and assembled spectrum context. Remove anchor-derived systemic redshift, write the fixed hypothesis redshift under `3a. Spectrum Summary` (no separate redshift section), and retain the separate second user turn for validated preliminary classification injection. The copied skill in `agenticGraphReasoningDesign/implement/` is a review draft; the legacy skill and batch path stay intact.
- 2026-10-16 — The decision owner restricted the first SH turn to CSV and report writing tools. The model reads precomputed Gaussian fits but cannot request new fits; unanswered consequential questions remain unresolved. The second turn exposes only classification submission. All three model-facing prompt files are English, with phase-one tools described in system and the phase-two tool described in the second user message.
- 2026-10-16 — The decision owner proposed measurement IDs in place of model-copied CSV numbers. The first SH node now accepts registry line IDs and run-local CWT/fit IDs in its write tool; code owns the numerical projection. This is a pilot of immutable observations and revisable judgments, not acceptance of the full live graph contract.
- 2026-10-16 — The decision owner moved ID assignment and hypothesis-targeted Gaussian prefits to the VI boundary. CWT IDs are shared across all hypotheses of one run; fit IDs include the hypothesis reference. New SH consumes the frozen VI catalog, with no fitting or ID assignment. The legacy comparison pipeline remains unchanged.
- 2026-10-16 — For FA `real_feature_or_not`, the decision owner requires an independent yes/no vote on the observed signal for each feature. The reviewer must not see proposed line identities or hypothesis context and has no third “insufficient evidence” answer. Code handles unusable windows before dispatch and computes the vote proportions after the specified odd number of valid sessions; these policies do not enter the individual prompt.
- 2026-10-16 — The decision owner also excluded measurement-source labels and source-derived fit/detection diagnostics from this FA prompt. A model-facing audit alias is unnecessary: one session has one target, so the write tool binds its binary answer to the measurement ID held by code. Only the candidate centre and emission/absorption direction identify where to inspect the raw local window.
- 2026-10-16 — Feature review scope follows the frozen VI IDs. CWT detections have one run-scoped identity shared across hypotheses; Gaussian fits have hypothesis-scoped IDs and are reviewed independently. FA votes on a fit affect only its hypothesis. Neither equal wavelengths nor similar fit centres justify merging fit entries across hypotheses or with CWT entries. Keep individual votes as records and derive the relevant entry's observed-signal state after the vote requirement is met; this state does not establish line identity.
- 2026-10-16 — The decision owner restricted SH first part to producing pre-analysis, without question-node generation. Questions and action selection belong to downstream reasoning after the SH/FA handoff. Returning to an analysis node creates a child branch of the reasoning trajectory; preserve parent results and every branch in a JSON export. The scientific feature graph and the branch lineage tree are distinct structures.

## Completion

- Earlier prototype status: the design sources and independent package entry point were preserved while the scoped feature and branch contracts were still open.
- 2026-10-16 — Implemented a reviewable SH pre-analysis slice: one English system prompt and two sequential English user prompts; an explicit adapter reuses legacy SH context/measurement tools, while the new node validates CSV → report → classification submission, preserves the locked Redrock redshift, and records a provisional scoped node value. This is a prototype of the first SH node, not completion of the graph, action, revisit or persistence contracts in this work package. The decision owner has not yet accepted the prompt wording.
- 2026-10-16 — QSO_4 hypothesis 2 smoke run: full prompt rendering passed; the `.env` configured model (`deepseek-flash`) completed CSV → report → classification submission with 25 CSV rows and `Type 2 QSO` at the fixed Redrock redshift 0.23787248591105023. The first two report writes were rejected solely for blank Markdown lines after headings; the third succeeded. The validator now accepts a machine-readable line as the first non-empty line below its heading, and replay of all three saved report drafts passes. Local ignored artifacts: `.data/runs/sh-pre-analysis-qso4-20261016/`. This is one real SH node smoke run, not graph-wide or independent scientific acceptance.
- 2026-10-16 — The ID-based SH pilot completed one additional real QSO_4 run. The model submitted 25 ID judgments with no numeric measurement fields; the first write incorrectly reused a doublet component for its blended label and was rejected, then repaired. Full-precision CSV, judgment sidecar, measurement catalog and report have matching node digests. The `MASKED` and failed-fit errors from the earlier run were absent. Scientific semantics for an unresolved blended line and report-prose consistency remain open; see `_aiHumanInteract/plan/evaluations/wp044-id-catalog-pilot-20261016.md`.
- 2026-10-16 — Added incremental Markdown archives for both SH sessions: system and user prompts, the complete stage-2 input transcript, returned assistant messages, tool calls/results and provider-returned reasoning when present. A real QSO_4 run produced both files with matching node digests; three older local smoke streams were reconstructed and labeled retrospective. Current DeepSeek calls returned no separate reasoning field. See `_aiHumanInteract/plan/evaluations/wp044-sh-session-archive-20261016.md`.
- 2026-10-16 — Implemented the explicit new VI measurement preparation entry point and made the SH adapter require its frozen per-hypothesis catalog. QSO_4 real NPZ with two Redrock hypotheses produced 54 shared CWT IDs, plus 10 and 3 hypothesis-scoped fit components. An SH handoff smoke rendered the second hypothesis context without an LLM call. See `_aiHumanInteract/plan/evaluations/wp044-id-catalog-pilot-20261016.md`. The graph-wide orchestrator and FA remain open.
- 2026-10-16 — Drafted English system and user prompts for FA's single-feature reality review in `agenticGraphReasoningDesign/implement/`. They preserve the useful local morphology/noise checks from legacy FA but omit line identities, whole-matrix instructions and vote percentages. No FA runner or live evaluation is claimed.
- 2026-10-16 — Designed SH batch submission in `agenticGraphReasoningDesign/implement/sh_parallel_submission.md`. The old runner submits one full hypothesis serially before bounded parallel fan-out; the new draft puts run-shared spectrum context before per-hypothesis facts and describes a two-request first wave for DeepSeek-compatible caching, followed by bounded parallel submission. At design time, cache hits, latency and provider behavior were unverified; no production scheduler was claimed.
- 2026-10-16 — Ran the six archived QSO_4 Redrock hypotheses through frozen VI measurements and the new two-stage SH boundary with a bounded two-seed submission probe. All six produced validated artifacts; two classified `Type 2 QSO` and four returned `null`/`unresolved`. One selected CWT feature completed one live FA reality session (`yes`). Added the single-feature FA runner and per-response provider usage archive. The probe scheduler exists only in the ignored local run script; the production graph orchestrator and run-shared prompt prefix are still open. Corrected duplicated Stage 1 usage carried into Stage 2 history without another API call. See `_aiHumanInteract/plan/evaluations/wp044-sh-fa-live-qso4-20261016.md` for counts and limits.
- 2026-10-16 — Completed the scoped SH→FA state and JSON branch contract. An offline QSO_4 replay imported all six validated SH nodes into 26 selected feature entries (19 shared CWT, 7 hypothesis-scoped fits). One real FA vote leaves the selected main branch pending; two clearly marked fixture votes on an unselected fork exercise quorum projection without scientific attribution. The fork retains its parent, all 9 branch events replay to their saved states, and 68 artifacts are copied into a SHA-256 checked export bundle. Focused tests cover feature scope, duplicate votes, historical fork snapshots, parent isolation, fixture-selection rejection and tampered SH imports. See `_aiHumanInteract/plan/evaluations/wp044-feature-branch-offline-qso4-20261016.md`. WP-045 owns downstream reasoning, live multi-reviewer FA, production scheduler and shared prompt prefix.
