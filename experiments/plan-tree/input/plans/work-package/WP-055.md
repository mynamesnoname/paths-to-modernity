# WP-055 — 记录 SH 失败原因并统一线表中心范围校验

## Objective

在 2026-10-30 的 249 条 BGS 批量运行中，10 条样本因单个 SH 假设失败而整条中止。失败档案只保存异常类名，7 条 `BadRequestError` 的具体提供方消息无法恢复；3 条 `ValueError` 则来自绘图守卫，而写表校验并不检查同一范围。本节点修复这两处可诊断性与校验一致性问题，不改变科学判定。

## Planned work

- 在 `GraphWorkflow` 的 SH 批量汇总中新增每个失败假设的 type、message 与 traceback；保留既有 `failed` 类型映射，并把原因摘要写入 `SHBatchIncompleteError` 文本。
- 让 `MarkdownSessionRecorder.finish` 接受错误消息与 traceback，并在 SH 会话归档中渲染。
- 在 `validate_sh_catalog` 的 kept 行校验中加入 `wavelength_min <= fitted_center <= wavelength_max` 检查，使越界中心在写表阶段以可修复原因返回，而不是写入 CSV。
- 保留 `plot_sh_adopted_lines` 的范围守卫，但让错误消息带出行名、中心与光谱范围，便于旧档案排障。
- 增加测试：失败摘要字段、会话错误记录、越界中心拒绝。

## Decisions

- 2026-11-02 — 失败详情采用附加字段 `failure_details`，`failed` 仍保持 ref → 异常类名，避免破坏现有读者；汇总 schema 升为 v2。
- 2026-11-02 — 中心范围作为写表边界的硬校验；绘图守卫保留为防御性断言，不改为静默跳过，以免掩盖真实的数据不一致。
- 2026-11-02 — 决策人裁定：**不做“单假设失败降级为部分完成”**。证据不完整时继续给出类型/红移会引入错误答案，因此保持“任一 SH 假设失败即该样本失败”的严格策略。
- 2026-11-02 — `continuation` 修复路径（7 条 `BadRequestError` 的直接触发点）不在本节点范围；根因分析见 `_aiHumanInteract/plan/evaluations/wp055-sh-failure-diagnostics-20261102.md` 的后续记录。

## Completion

- 状态：**done**（2026-11-02）。失败详情与中心范围校验均已实现：`sh_batch_summary.json` 记录 type/message/traceback，SH 会话 Markdown 记录错误消息与 traceback，写表校验拒绝越界的 kept 中心。
- 验证：`tests/agentic_graph` 196 条通过（新增 2 条），定向 18 条通过，计划校验与生成视图一致。
