# ST-012 — Live ontology and graph closure

## Scope

Finish the path from observations to conclusions in the active Redrock batch workflow. Treat the existing typed registry and graph as the runtime base; neither a graph database nor RDF serialization is required for this acceptance. Keep the graph usable from saved artifacts without model calls.

## Sequence

1. `WP-035` writes model-derived hypotheses, claims, line identities and audit outcomes into the live graph with typed links.
2. `WP-036` defines reproducible queries, validates cross-layer references and records whether each rule actually affected a decision.
3. Existing `WP-031` completes the distinct missing-line observation and context-specific finding path against the same graph contract.
4. `WP-037` performs real graph-chain and independently labeled classification/redshift acceptance after those paths and `WP-040`'s parameter work are ready. `WP-012` separately owns independent defect-severity validation.

## Decisions

- The user asked to close the implementation gap after a code-level review; `REQ-009` preserves the observed gap and boundaries.
- `ST-010` still owns migration of active knowledge authority and `WP-031`; this node owns the wider graph and final queryability. `ST-011` still owns prompt assembly. Shared code does not merge their acceptance claims.
- Graph evidence must never turn an unobserved or ambiguous line into negative physical evidence by itself.

## Completion

- Planned. No implementation or new live run is claimed by this plan.
