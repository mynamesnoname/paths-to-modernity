# WP-027 — Prompt and behavior verification

## Objective

Verify the rendered context and the scientific and software contracts before activating reorganized prompts in production runs.

## Planned work

- Add focused render tests with representative and adversarial fixtures, checking behavior-relevant facts rather than incidental spacing.
- Exercise downstream CSV, report and summary parsing, missing-data handling, failure classification, and clean retries.
- Compare the complete effective context for ontology authority and truth-label leakage; keep version/digest evidence with the run.
- When implementation is ready for release, run representative FITS/LLM comparisons under the existing compatibility policy and record cost and scientific differences. This planning turn performs no live run.

## Decisions

- A provider-native structured-output path is evaluated only if endpoint capability is proven; otherwise validate the current outputs.

## Completion

- Planned; blocked by WP-026.

## Evidence

- To be recorded from fixture tests, prompt authority audit, output checks and the eventual comparison record.
