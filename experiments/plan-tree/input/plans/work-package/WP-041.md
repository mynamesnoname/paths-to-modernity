# WP-041 — Freeze declared parameters per run and trace prompt authority end to end

## Objective

Each run should hold **one** immutable set of declared parameters. Declaration-derived
guidance numbers in model-facing prompts should link to their effective authority;
observational measurements should remain identifiable as run data.
The verified pre-change system did not provide those guarantees.

每个运行应当持有**唯一**一份不可变的已声明参数集合，且每份面向模型的提示词都应能追溯到产生其中
指导性数值的那些声明；观测数值则应标识为运行数据。下文记录的是修改前的缺口。

## The problem, as verified on 2026-10-15

1. **Consumers reload the configuration independently.** There are 33 direct loader call
   sites (`load_analysis_method` / `load_rule_parameters` / `load_model_calls`) and 75
   when the effective-value readers (`effective_parameter`,
   `effective_operand_threshold`, `rule_condition_bound`) are included. The survey
   recorded 37; the count is of that order either way.
   **消费方各自独立重载配置**：直接加载器调用点 33 处，含"生效读取"则为 75 处。
2. **The loaders do not cache.** `load_analysis_method()` re-reads and re-validates the
   JSON file on every call, so each decision point samples the file at its own moment.
   **加载器没有缓存**：每次调用都重新读文件并重新校验。
3. **The record is a snapshot, not a proof.** `effective_parameters.json` is written once,
   at result-writing time (`ResultWriter.write_effective_parameters`,
   `result_writer.py:114`), while the readers may have sampled the file earlier or later.
   So the run records *a* value set but cannot prove which one any stage used.
   **记录是写结果那一刻的快照**，无法证明某阶段当时用的是哪一组值。
4. **The prompt authority link is missing.** Stage `stream.md` artifacts already archive
   full prompts and tool results. `inspect_prompt_leakage.py` archives only digests,
   lengths and findings in its *inspection output*. Neither artifact maps a governed
   guidance number to its declaration; a pair of digests cannot prove that mapping.
   **提示词与声明的联系缺位**：阶段 stream 已保存完整提示词和工具结果；泄漏检查器仅在检查
   产物中存摘要。两者都没有把受治理的指导数值逐项映射到声明，两个摘要值也无法证明映射。

Consequences: a long run can use two different value sets without any check noticing
(a file edited mid-run, a subprocess with a different `FORMA_ANALYSIS_METHOD`, or batch
mode re-reading between files); a review cannot verify which bound a decision used; and
"where did this number in this prompt come from?" is unanswerable from the artifacts.

后果：长运行可能在无人察觉的情况下用到两组值；复盘无法核验某次判定用的是哪个界；"提示词里的这个
数字来自哪里"无法从产物回答。

## Planned work

1. **Freeze once.** One entry point loads the declared JSON into an immutable object
   (analysis method, rule parameters, model calls) and computes a content digest; the
   digest is written into `effective_parameters.json` and the telemetry.
2. **Thread it.** Decision points read the frozen values through the existing loaders,
   which return copies of the run snapshot. The source guard prevents direct file reads
   outside those loaders.
3. **Trace prompt authority.** Each stage records the digest of its initial model-facing
   system+user prompt and a per-value manifest (declaration ID, effective value, unit,
   source and location/template binding) for declaration-derived guidance numbers. Distinguish
   observational measurements from governed guidance. The new trace does not duplicate
   prompt text already present in stage streams.
4. **Guard and test.** A source guard fails when stage code reads declaration files directly; a test
   proves that editing the configuration mid-run cannot change a stage's values; a test
   proves the same frozen configuration and stage inputs re-render the same initial
   prompt; later prompts may differ when model outputs differ.

## Decisions

- **Dependency boundary — clarified 2026-10-16.** WP-041 builds on the completed
  ontology cutover and parameter override contract (WP-023/WP-038) and the
  declarations already delivered in WP-040. It does not require WP-040 to close:
  WP-040's original every-run effective-value acceptance needs this freeze and
  trace work. Requiring WP-040 to finish first would block both packages.
- **Recorded, not decided** (2026-10-15, decision owner): this item is architecture rather
  than numeric declaration, so it becomes its own node under ST-010 instead of staying
  inside the empirical-parameter survey. The survey's item 10 is handed over here.
- **Freeze granularity — clarified 2026-10-16.** Freeze once per spectrum run, matching
  the objective. A batch may use a different frozen configuration for each spectrum;
  every spectrum records its own digest. Process-wide caching would not meet this contract.
- **Subprocess boundary — decided 2026-10-16.** The decision owner chose **record
  external authority**. Every actual Redrock invocation records the command, resolved
  launcher, template/archetype content hashes, selected environment and return code.
  This allows different Redrock versions/templates between runs; comparing outputs
  requires comparing their external-authority records as well as the frozen FORMA
  parameter digest. It does not claim bitwise replay or detect files changed during
  subprocess execution. Strict hash enforcement is outside this decision.
- **Prompt trace shape — clarified 2026-10-16.** Keep a digest of the final prompt plus
  an authority manifest for governed guidance values. Existing stream artifacts already
  contain full prompt text; whether to retain or redact those streams is a separate
  retention decision, not solved by using digests in this new trace.

## Progress 2026-10-16

- `frozen_parameters.py` now takes a per-spectrum snapshot of the three declared JSON
  sources. A task-local context carries it through the graph; loader results are copies,
  so callers cannot mutate the retained set. A second spectrum resamples its own files.
  The run snapshot and telemetry record the digest. The result writer's former undefined
  `document` reference was repaired, so the record can actually be written.
- Initial system+user prompt pairs now have SHA-256 and per-slot authority entries next
  to their stage streams. A hypothesis-specific filename prevents parallel SH hypotheses
  from overwriting one another. The extraction fallback also records its prompt pair.
  Measurements from the spectrum and model-generated text are deliberately outside the
  declaration manifest. The rendered-prompt number audit remains a *report*: its
  value-matching heuristic is not proof of complete authority coverage.
- The Redrock runner now writes an external-authority record containing argv, launcher,
  template/archetype hashes and selected environment. The decision owner selected this
  recording policy; the external boundary note states its replay limits.
- Targeted freeze, prompt-authority, result-writing and Redrock tests pass. The full
  offline suite ran 794 tests and passed (3 skipped). A real `ELG_6` run is underway
  to inspect all new artifacts at their actual stage paths. The source-digest fixture
  is rebuilt after the last source edit.

## Completion

Accepted 2026-10-16. The final `ELG_6` Redrock + LLM run exited successfully and
produced a six-section report and structured brief. The frozen digest matched in
the effective-parameter record, telemetry and all nine stage manifests. Each
manifest's initial system+user digest was recomputed from its archived stream;
all nine matched, with 288 declaration-value entries in total. Mid-run edit,
path-change, snapshot isolation, source-guard and deterministic rendering tests
passed. The full offline suite passed 800 tests (3 skipped). The Redrock record
contains actual argv, launcher/source and template/archetype digests, selected
environment and return code, under the decision owner's record-only policy.

The live run also exposed a Report Writer turn ending immediately after tool
results. Bounded continuation was added and exercised by a focused test;
report-file preservation and the CLI completion gate were verified in the
final run. Details and limits are in
`_aiHumanInteract/plan/evaluations/wp040-wp041-closure-20261016.md`. The manifest is about
registered declaration-derived guidance values; a prose literal outside the
builder is reported by the separate heuristic audit, not certified by the
manifest. Scientific calibration is outside WP-041.
