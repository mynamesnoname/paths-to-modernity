# WP-040 — Declared empirical parameters, values from config

## Objective

The decision owner's criterion: a judgement number that encodes *how we choose to
judge* is an empirical knob and may be configured by the user; a physical or
structural fact may not.  This package moves the empirical knobs into the ontology
as **declarations** and takes their **values** from validated JSON, keeping
ontology, prompts, skills and the knowledge base in step by construction.

## Planned work

- Add a registry record family for empirical parameters (scalar, threshold and
  trapezoid memberships) with unit, default, basis, citations and consumer, plus a
  declared source per parameter so a value that *is* a rule bound is derived from
  that rule instead of restated.
- Generalise the validated override payload introduced by `WP-038` (rule operand
  thresholds) so it covers declared parameters of every kind, rejecting unknown
  ids, non-finite/out-of-domain values and shape violations.
- Evaluate the fuzzy predicates from the registry; keep the four convenience
  functions as thin wrappers so existing consumers and tests keep working.
- Make the prompt-authority audit compare prose against **effective** values and
  report each value's source (registry default or config override) and digest.
- Declare the remaining code-owned empirical numbers reported by the ownership
  survey; record the excluded physical/structural facts as the boundary.

## Decisions

- Ownership, decided by the decision owner on 2026-10-13: the **registry declares**
  a knob (id, unit, default, basis, consumer), the **config supplies** its value.
  This follows the `WP-038` shape rather than inventing a further surface, and it
  keeps the earlier rules: config cannot add a knob the registry did not declare,
  illegal values are refused, and every run records value/unit/source/digest.
- Empirical knobs are user-configurable **because** they are conventions, not
  measurements; the price is recording and comparability, so a parameter difference
  must be an explicitly declared difference rather than an unexplained result
  change.
- Where a membership endpoint is the same bound as a rule threshold, the endpoint
  is derived (not restated); shape-only endpoints stay membership-owned.
- `WP-012` owns the *calibration* of these predicates and is still `in_progress`, so
  it is linked rather than declared a hard prerequisite: this package changes where
  a value is declared and how it is supplied, not which value is scientifically
  right.  The declaration ids and the membership shapes are kept stable so the
  calibration work can override values through the same payload.
- Physical and structural facts are excluded by construction and enumerated in the
  survey rather than left implicit.
