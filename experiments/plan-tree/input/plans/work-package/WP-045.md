# WP-045 — Downstream progressive disclosure and action loop

## Objective

Build the downstream reasoning pilot after fixed SH pre-analysis and FA feature review.

## Planned work

- Derive downstream questions and routing decisions from the SH pre-analysis artifacts and scoped FA feature states; do not require SH first part to generate them.
- Add focused graph query and bounded action interfaces for the later reasoning stage.
- Connect tool outputs to scoped feature and hypothesis states on the active branch and record action provenance.
- Preserve branch lineage and all analysis artifacts when a later stage revisits an analysis node.
- Split SH's first user message into a frozen run-shared prefix and a per-hypothesis suffix; submit independent two-stage sessions with bounded concurrency and record real provider cache-usage fields.
- Complete `real_feature_or_not` across all SH-selected features: independently collect the declared odd quorum with bounded concurrency and retries, record failed attempts and unusable windows without fabricating votes, and persist each result on its branch.
- Add a hypothesis-scoped Lyα forest observation node for kept SH Lyα claims. Record blueward coverage and independent visibility votes as advisory information for future HS/RA; keep it out of feature-reality state and type gates.
- Add a hypothesis-scoped doublet review for complete and orphan SH claims using ontology component identities, frozen VI measurements and branch-local FA feature states. Keep its independent pair vote separate from both component reality votes.
- Consolidate repeated FA vote-session execution and cache-usage accounting while preserving each node's scientific preflight, output interpretation and branch mutation boundary.
