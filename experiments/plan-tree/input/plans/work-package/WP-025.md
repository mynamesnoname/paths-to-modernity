# WP-025 — Prompt input and provenance contract

## Objective

Define what each stage is allowed to put into model context and how a run records the exact effective context safely.

## Planned work

- Inventory active system prompts, Python user-message builders, tool descriptions, generated ontology pages, and prior-stage reports.
- Define typed input objects or validated schemas, with explicit units, optionality, missing/masked semantics, source identities and trust boundaries.
- Specify canonical rendering inputs and version/digest recording. Ensure secrets are excluded from stored traces.
- Choose a compact representation for repeated observations based on measured token use, without silently dropping evidence.

## Decisions

- The existing local Markdown instructions and Python code are the baseline. This work package specifies interfaces; it does not authorize a provider or framework migration.

## Completion

- Planned; not started.

## Evidence

- To be recorded after the schema, inventory and provenance contract are reviewed.
